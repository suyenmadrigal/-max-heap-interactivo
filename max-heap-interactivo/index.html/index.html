Montículo Binario (Max-Heap)

Aprende la estructura de datos con teoría, analogía, laboratorio y mini-juego

¿Qué es un Max-Heap?

Un heap o montículo es una estructura de datos basada en un árbol binario completo. Esto significa que los niveles se llenan de izquierda a derecha y no existen huecos antes de los últimos elementos.

Existen dos variantes principales: Max-Heap y Min-Heap. En un Max-Heap, cada padre debe ser mayor o igual que sus hijos.

Padre ≥ hijo izquierdo y Padre ≥ hijo derecho

Importante: el Max-Heap no ordena todos los elementos. Solo garantiza la relación entre cada padre y sus hijos. Por eso dos hermanos pueden estar en cualquier orden.
🏆

Analogía: un torneo donde el ganador sube

Imagina un torneo de eliminación en el que cada participante se enfrenta indirectamente con otros jugadores. En cada grupo, el participante con mayor puntuación queda por encima de sus competidores.

El jugador que termina en la parte superior representa la raíz del Max-Heap y siempre contiene el valor máximo. Cada jugador debajo de él representa un hijo.

Si aparece un jugador con una puntuación mayor que la de su padre, se intercambian sus posiciones. El jugador más fuerte va subiendo hasta encontrar una posición donde vuelva a cumplirse la regla.

Esto es exactamente lo que ocurre durante una operación de inserción: el nuevo elemento entra al final y flota hacia arriba mediante intercambios.

Cuando eliminamos al máximo, el último elemento ocupa temporalmente la raíz y después se hunde hasta encontrar una posición válida.

Cumple la regla

Válido: ningún hijo supera a su padre.

Rompe la regla

Inválido: el hijo 80 supera a su padre 50.

¿Cómo se almacena?

Gracias a que el árbol es completo, no necesitamos utilizar referencias o punteros para cada hijo. Podemos guardar todos los valores directamente dentro de un arreglo.

Para un elemento situado en el índice i:

  • Padre: Math.floor((i - 1) / 2)
  • Hijo izquierdo: 2 * i + 1
  • Hijo derecho: 2 * i + 2

Operaciones principales

  • Insertar: se coloca el elemento al final y después se hace sift-up.
  • Extraer máximo: se elimina la raíz y el último elemento se mueve hacia arriba para después hacer sift-down.
  • Consultar máximo: basta con leer la raíz.

Análisis de rendimiento — Big O

La altura de un heap binario es logarítmica respecto al número de elementos. Por eso las operaciones que recorren el árbol de arriba hacia abajo o de abajo hacia arriba suelen costar O(log n).

Operación Complejidad ¿Por qué?
Consultar máximo O(1) El máximo siempre está en la raíz.
Insertar O(log n) El elemento puede subir como máximo una altura del árbol.
Eliminar máximo O(log n) El último elemento puede descender por varios niveles.
Buscar un valor arbitrario O(n) El heap no está completamente ordenado.
Construir heap desde un arreglo O(n) El algoritmo bottom-up puede construirlo linealmente.
¿Cuándo conviene? Un Max-Heap es ideal cuando necesitamos consultar o eliminar repetidamente el elemento de mayor prioridad.
¿Cuándo no conviene? No es la mejor opción cuando necesitamos buscar rápidamente cualquier elemento concreto. Para eso pueden ser mejores estructuras como una tabla hash o un árbol de búsqueda balanceado.

Aplicaciones en el mundo real

🚦 Colas de prioridad

Los sistemas pueden almacenar tareas según su prioridad. El elemento con mayor prioridad se obtiene rápidamente mediante la raíz del Max-Heap.

🎮 Sistemas de videojuegos

Un juego puede utilizar heaps para administrar eventos, enemigos o acciones que deben procesarse según una prioridad determinada.

📊 Heap Sort

El algoritmo Heap Sort utiliza un heap para ordenar elementos y garantiza un tiempo de O(n log n) en su funcionamiento.

🗺️ Algoritmos de grafos

Estructuras basadas en heaps se utilizan para administrar prioridades en algoritmos como Dijkstra y Prim.

💻 Sistemas operativos

Los conceptos de colas de prioridad y heaps pueden utilizarse para organizar procesos o tareas según niveles de prioridad.

🔎 Procesamiento de datos

Los heaps son útiles para obtener rápidamente los elementos con valores más altos o mantener rankings dinámicos.

Código base de un Max-Heap en JavaScript

Esta es una implementación básica de las operaciones fundamentales: insertar, consultar el máximo y extraer el máximo. 

class MaxHeap {
  constructor() {
    this.heap = [];
  }

  parent(i) {
    return Math.floor((i - 1) / 2);
  }

  left(i) {
    return 2 * i + 1;
  }

  right(i) {
    return 2 * i + 2;
  }

  insert(value) {
    this.heap.push(value);

    let i = this.heap.length - 1;

    // Sift-up
    while (i > 0) {
      const p = this.parent(i);

      if (this.heap[p] >= this.heap[i]) {
        break;
      }

      [this.heap[p], this.heap[i]] =
        [this.heap[i], this.heap[p]];

      i = p;
    }
  }

  peek() {
    return this.heap.length > 0
      ? this.heap[0]
      : null;
  }

  extractMax() {
    if (this.heap.length === 0) {
      return null;
    }

    if (this.heap.length === 1) {
      return this.heap.pop();
    }

    const max = this.heap[0];

    this.heap[0] = this.heap.pop();

    // Sift-down
    let i = 0;

    while (true) {
      const left = this.left(i);
      const right = this.right(i);

      let largest = i;

      if (
        left < this.heap.length &&
        this.heap[left] > this.heap[largest]
      ) {
        largest = left;
      }

      if (
        right < this.heap.length &&
        this.heap[right] > this.heap[largest]
      ) {
        largest = right;
      }

      if (largest === i) {
        break;
      }

      [this.heap[i], this.heap[largest]] =
        [this.heap[largest], this.heap[i]];

      i = largest;
    }

    return max;
  }
}
